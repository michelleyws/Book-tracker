# Book-tracker · 书籍购入记录

一个**给自己用的**藏书台账：记买了哪些书、花了多少钱、在哪儿买的、读没读完，以及订阅盒子（book box）什么时候扣款、这期是什么书、这一年还能 skip 几次。

- **在线使用**：<https://michelleyws.github.io/Book-tracker/>
- 纯前端单页应用：**没有构建步骤**，没有框架，没有后端，不需要装任何东西。数据全部存在**你自己浏览器的本地存储**里，不上传、不同步、没有账号。

手机建议用 Safari/Chrome 打开后「添加到主屏幕」，用起来和 App 一样。

## 功能一览

### 📚 书库
- 记录字段：书名、作者、系列、ISBN、类型、状态（已到手 / 买了·没到手 / 未入手）、装帧、阅读状态、评分、读完日期、购入日期、价格 + 币种、购入来源、购买链接、出版社、备注、Goodreads 链接、封面。
- 搜索框一个框搜全部（书名/作者/系列/日期/价格/备注…）；按状态、类型筛选；按购入日期、价格、系列排序。
- **多币种记账**：价格可记 CNY / USD / GBP / AUD / EUR / CAD / JPY / HKD / SGD / NZD / CHF，合计自动折成人民币；汇率可手动改、也可一键联网更新（`open.er-api.com`），并显示「汇率来自哪一天」。**缺汇率的记录会被单独标出来、不计入合计**，不会静默按 1:1 算。
- 长按（手机）或右键（电脑）进入多选模式，可批量删除 / 批量改状态。
- 卡片左侧显示封面缩略图（可选，见下）。

### 🔎 从 Goodreads 自动填
输入书名点「获取」→ 列出 Goodreads 上的候选书 → 选中后自动填**作者、系列名、同系列其他书目、以及书页/作者页/系列页三个链接**。
作者链接是**从书页上点作者名拿到的那条**，所以不会出现「同名不同人」填错的情况。同系列书目**不会整批导入**，一律先给你勾选。

> 通道走你自己在「设置」里填的 Jina 代理 Key，用于绕过 Goodreads 的反爬。Key 只存在你自己的浏览器里。**仅供个人自用，不要对外发布**——Goodreads 的服务条款允许个人非商业用途。

### 📖 阅读记录
第三个标签页。把书标成「在读 / 已读」，填评分和读完日期，就会汇总成阅读记录：已读本数、在读本数、本月读完、平均评分，按读完日期倒序排列。

### 📦 订阅盒子（book box）
- 每个订阅记录：名称、周期（每月 / 每两月）、扣款日、默认金额 + 币种、年度 Skip 配额、官网数据源、备注。
- 每个订阅下按**期次**记录：本期扣款日、实际扣款金额、状态（待扣款 / 已扣款 / 已跳过 / 已取消）、本期书目（跟书库一样能填作者、系列、Goodreads 链接）。
- **扣款提醒**：页面顶部会按「还有几天扣款」排序提醒；「跳过」有截止日的话也会提示。
- **标记已扣款时，本期书目会自动进书库**（状态 = 买了·没到手，来源 = 订阅名，金额 = 本期实际扣款），不用手抄一遍。
- **Skip 配额**：每家 bookbox 的年度跳过次数不一样，各自单独设。点一次「跳过这期」自动 +1，改回其他状态会 −1；剩 1 次变黄提醒、用完变红提醒；跨年自动把「已用」清零。
- 可导出 `.ics` 日历文件，把扣款日（含提前 7 天 / 1 天提醒）一次导进手机日历——因为静态网页做不到关着页面还推送。

### 🖼 封面（可选，存本机）
- 手机：点「选图片 / 拍照」；电脑：直接 **Ctrl+V** 把截图粘进来，也可以把图片拖进去。
- 出来**四个可拖动的角点，按书的四个角对上去**，确认后自动做**透视校正**（斜着拍的会被掰正），压缩后存起来。也有「自动找边」先给个大致范围，再手动微调。
- **图片存在浏览器 IndexedDB 里，不占书库数据的空间**（localStorage 只有 5MB，一张手机照片就有几百 KB，存十几本就会连文字记录一起写不进去）。封面完全可选，不加不影响任何功能。
- ⚠️ **导出的 xlsx 不含封面图片**。图片只在本机浏览器里活着，清理浏览器数据就会没。

### 📥 导入 / 📤 导出
- 导出 xlsx，**系列名和作者名两列带超链接**（Goodreads 链接）。
- 导入 `.xlsx`（腾讯文档那种）或 `.csv`：自动识别 **UTF-8 / GBK** 编码，自动识别逗号 / 分号 / 制表符分隔，表头认中英文别名。
- 匹配顺序：**ISBN → 书名+作者 → 书名唯一**（中文表格常把作者写成译名，例如「休·豪伊」vs「Hugh Howey」，只按书名+作者会认不出来、白白多一条重复记录；按「书名唯一」匹配上的行会在确认框里单独计数，方便你核对）。
- **CSV 里空白的字段不会覆盖已有资料**；写入失败（手机存储满）会整体回滚，不留半截数据。

## 数据存在哪 / 怎么备份

| 内容 | 位置 |
|---|---|
| 书籍记录 | `localStorage["bookRecords.v1"]` |
| 订阅盒子 | `localStorage["bookSubs.v1"]` |
| 汇率 + 汇率日期 | `localStorage["fxRates.v1"]` / `fxRatesAt.v1` |
| Jina Key | `localStorage["grProxyKey"]` |
| **封面图片** | **IndexedDB**（库 `booktracker`，表 `covers`） |

同源下所有数据都属于 `https://michelleyws.github.io/Book-tracker/`。**更新代码不会动你的数据。**

备份建议：定期点「导出」存一份 xlsx。注意 xlsx 只有文字和链接，不含封面图；清理浏览器数据 = 封面丢失。

## 订阅数据的自动同步

订阅盒子的「扣款日 / 最后可 skip 日 / 费用 / skip 政策 / 下一期书目 + 封面 + 装帧细节」来自
<https://www.booksandspreadsheets.com/>（感谢站主维护这份数据库）。

那个站没有开放 CORS 接口，所以**不在网页里直接抓**，而是用 GitHub Actions 每天抓一次、生成**同源**的 `bs-subs.json`：

- `.github/workflows/sync-bs.yml` —— 每天 05:17 UTC（北京时间 13:17）跑一次，也可以在仓库 Actions 页面手动 `Run workflow`。
- `sync_bs.py` —— 只用 Python 标准库；抓完写 `bs-subs.json` 并提交回仓库（没变化就不提交）。
- 站点是 Wix CMS，数据以 JSON 内嵌在 SSR 的 HTML 里，脚本按大括号配对定位、再用正则取字段（该 JSON 本身有瑕疵，不能整体 `json.loads`）。

App 打开时会静默读一次这份 JSON，用来显示官网规则；真正的「套用官网数据」（填扣款日、建期次）仍然只在点「🔄 同步官网数据」时执行——**只会填本地没设过的字段，绝不覆盖你手改过的值**。

**想加别的订阅**：把它的 slug 加进 `sync_bs.py` 顶部的 `SOURCES` 列表（slug 就是 `/companies/<slug>` 那一段），再提交一次即可。

订阅名字**支持缩写**：`TBB` / `The Broken Binding` 都会绑到 Broken Binding，`EK` / `Eldritch King` 都会绑到 Eldritch King，Bookish & Spice 写 `Bookish and Spice` / `B&S` 都认。

## 文件结构

```
index.html                          全部页面与弹层
style.css                           唯一一份样式（CSS 变量 + .tag/.btn-small/.sheet 等类名）
app.js                              唯一一个 IIFE：存储、渲染、表单、Goodreads、导入导出、订阅、封面
vendor/xlsx.full.min.js             SheetJS（xlsx 读写）
vendor/jszip.min.js                 JSZip（从 xlsx 里解出超链接）
bs-subs.json                        GitHub Action 每天抓的订阅数据（App 同源读取）
sync_bs.py                          抓 booksandspreadsheets.com 的脚本
.github/workflows/sync-bs.yml       每天定时抓取
assets/                             背景图
```

> 仓库里还留着早期布局的副本（`tools/sync_bs.py`、`data/bs-subs.json`）。**实际生效的是根目录那份**：workflow 跑的是根目录的 `sync_bs.py` 并提交根目录的 `bs-subs.json`。改的时候别改错文件。

## 改代码 / 部署

没有构建步骤，改完提交即上线：

1. 直接改 `index.html` / `style.css` / `app.js`；
2. 提交到 `main` 分支 → GitHub Pages 自动发布（约 1 分钟后生效，CDN 最长缓存 10 分钟）。

本地预览：直接双击 `index.html` 就能用（`file://` 下 localStorage 和 IndexedDB 都正常）。
唯一例外是读 `bs-subs.json` 需要 `fetch`，`file://` 下会被浏览器拦掉——那部分显示不出来，功能本身不受影响。想完整预览就起个本地静态服务器。

**注意**：仓库里的文件用 **LF 换行**。用 Windows 编辑器改成 CRLF 会把一行改动变成整个文件的 diff。

## 已知限制

- **Goodreads 是唯一元数据源**，反爬很强，所以走 Jina 代理 + 你自己的 Key；被限流时会失败，重试即可。目前没有换商用源的打算（对外发布需要换授权数据源，且 Goodreads 的条款只允许个人非商业用途）。
- **自动找边只对「书大致摆正、背景颜色不同」的拍法准**（实测正拍能准到 1 像素）；斜着拍只会给一个大致范围，需要手动拖四角——透视校正会负责把它掰正。
- **网页条码扫描依赖 `BarcodeDetector`，iOS Safari 不支持**，所以 iPhone 上这条路走不通，用「选图片/拍照」即可。
- **同名书合并需要人工判断**：即便按「书名唯一」匹配上了，确认框也会单独提示，请你核对。
- **订阅提醒只能做到「页面开着的时候」**：静态网页没有后台推送能力，所以扣款提醒靠页面倒计时 + 导出 `.ics` 到系统日历。
- **Eldritch King 不在 booksandspreadsheets.com 收录的 245 家之列**——它是 Curious King 团队 2026 年新开的
  恐怖 / 暗黑小说品牌（官网 <https://eldritchking.com>），所以它的规则是**写在代码里的手工数据**：
  双月刊 6 期/年、每年可跳 1 期（官网原文 *You may skip one title per year*）、Blood Pact £30 布面 /
  Soul Pact £40 皮面、首期《World War Z》(Max Brooks) 预计 2027 年 3 月发货。官网改了要自己更新。
- 汇率默认值是内置参考值，用之前建议先点一次「联网更新汇率」。
